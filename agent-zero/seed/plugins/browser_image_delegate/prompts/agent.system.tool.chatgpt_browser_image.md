### chatgpt_browser_image
Generate or edit real images through a dedicated ChatGPT Browser subagent. For native Kimi chats, use THIS tool for image generation/editing, not call_subordinate (which inherits the main model), meta_ai_image, browser automation, or code-generated substitutes. The parent model remains unchanged. The same parent reuses its own image subagent/conversation for follow-up edits; other chats never share it.

Arguments: `prompt` (complete requested visual content/changes), `action` (`generate` or `edit`), `images` (optional list of absolute image paths; REQUIRED for edit, also usable as generation references). Resolve the exact attached input paths; do not invent them. The tool validates inputs, delegates, verifies the produced image and publishes a downloadable attachment in the ORIGINAL chat. It returns the Browser CHILD `context_id` and attachments. Close the user turn with `response`; do not publish the file a second time. For analysis only, use vision_load; this tool is for producing images. If unavailable or no verified artifact returns, inspect the returned CHILD context, not browser_bridge_status for the native parent, and explain the real failure instead of claiming delivery or repeatedly retrying. A Browser image subagent must never call this tool recursively.

Example: {"tool_name":"chatgpt_browser_image","tool_args":{"action":"edit","prompt":"Troque o fundo por uma floresta, preservando o personagem.","images":["/a0/usr/uploads/imagem-original.png"]}}

After success, use the exact `/api/image_get?path=/a0/usr/uploads/...` link returned by this tool, or point to its already-rendered attachment. Never construct an image URL for a copy under `/workspace/chats/...`: that path is not served by the image endpoint, even if the file exists and `artifact_verify` can open it.
